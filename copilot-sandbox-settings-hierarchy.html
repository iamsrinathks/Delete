How the layers combine

For most managed keys the highest source wins (MDM > server > file > user). The sandbox key is the exception: all managed sources and the user's settings combine in the most restrictive direction.

Client-specific gotchas

VS Code — docs conflict. GitHub's reference lists sandbox for VS Code Agent Host (1.138+, minimum 1.141.0). VS Code's enterprise guide says that reference does not list it, and managed sandbox enforcement is in Preview. Verify with /sandbox policy and Developer: Policy Diagnostics on a canary.
VS Code — bypass default differs. When managed enabled: true is set and allowBypass is omitted, VS Code locks the session toggle on. The CLI treats omitted as allowed.
VS Code — harness side-effects. Any managed settings disable the Claude and Codex harnesses. Managed sandbox.enabled: true routes new sessions to the Copilot harness unless vscode.temporaryDefaultToLocalHarness: true (1.142+). The Local harness ignores runtime sandbox rules and is unsandboxed on Windows.
Copilot app. Project settings show only what the user asked for, not the effective managed policy, and show no per-setting locks. The embedded runtime still enforces the full managed sandbox object.
Windows network rules are guardrails. Host rules and proxies rely on programs honouring proxy settings, and need allowLocalNetwork: true. Keep corporate egress controls in place.
