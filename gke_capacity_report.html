How to read and use this report

Read the charts

  • Start with the sizing chart. It shows one bar for each reservation you need.
  • Compare the black line with the bar. The gap is your unused reserved capacity.
  • Check the usage chart for zones that peak higher than other zones.
  • Check the autoscaler table for failed scale-ups. They show real stockouts.

Make the report

  1. Run the script once for each cluster.
  2. Open report.html from the output folder.
  3. To compare clusters, load more report_data.json files here.
  4. Or merge them with the build-html command.
python3 gke_node_peaks.py build-html \
  --out all-clusters.html \
  node-peaks-*/report_data.json

Know the limits

  • A reservation holds VM capacity only. It does not schedule Pods.
  • Pods also need correct requests, tolerations and quota.
  • A specific reservation caps pool history. Real demand can be higher.
  • The sizing input is a starting point. Review it before you reserve.
